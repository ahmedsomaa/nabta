LLM Integration

Document use cases and integration patterns. No implementation in current phases.

Use Cases

Use CaseIntegration Pattern
Assignment feedback assistTeacher-triggered, human-in-the-loop review before sending to student
Student study helperScoped to enrolled subject content only; no open-ended web access
Admin insightsNatural language queries over school analytics data
Content draftingTeacher lesson and announcement draft suggestions

Architecture Principles

  • Provider abstraction: LlmService interface — swap OpenAI, Anthropic, or local models without changing business logic
  • School-level opt-in: each school enables/disables AI features independently
  • Data boundaries: no student PII sent to LLM without explicit consent
  • Audit logging: all AI-generated content logged in AuditLog
  • Rate limiting: cost controls per school (token budgets)
  • Human-in-the-loop: teachers review AI suggestions before publishing to students
