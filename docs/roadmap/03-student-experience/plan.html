Phase 3 Complete Historical execution plan — student portal, student-scoped APIs, and seeded Grade 10 Mathematics content.

Companion to Phase 3 — Student Experience (scope guards and acceptance criteria). This page is the execution plan: models, student APIs, seed data, and apps/web screens. Slices 0–1 are data/API prerequisites; slices 2–6 map to the five user-facing slices on the phase index.

Web student portal only. Teacher create/grade is Phase 4. Quizzes are Phase 5. Keep /student/grades as an explicit later-phase placeholder. Phase 3 seeds published lessons and assignments so the student flow is real without teacher CRUD.

Slice order

Slices 0–1 first (nothing to show without content and APIs). Then dashboard → classes → lessons → assignments → UX polish. Sequential; each slice is independently verifiable.

Slice 0 — Content models + demo seed

Goal: persist units, lessons, timetable, assignments, submissions, and progress. Tenant isolation on every query (schoolId from JWT context, never from the body).

Models: Prisma in packages/database/prisma/schema.prisma. All school-owned entities: UUID id, schoolId, createdAt, updatedAt.

ModelRole
UnitOrdered block under Subject (optionally scoped to class)
LessonUnder Unit. type: RICH_TEXT | VIDEO | PDF | IMAGE | EXTERNAL. Body/url fields — not blobs in PostgreSQL
LearningMaterialFile metadata on a lesson (storageKey, mimeType, size, checksum)
TimetableSlotWeekday + start/end + room + classId + subjectId. Enough for “today’s schedule” without a timetable admin UI
AssignmentTitle, instructions, dueAt, subjectId, classId, publishedAt. No teacher POST in this phase
AssignmentSubmissionPer student. Status: DRAFT | SUBMITTED | LATE (set LATE on submit if after dueAt). Enum may include GRADED / RETURNED but unused until Phase 4
SubmissionFileMetadata for uploaded files
LessonProgressstudentId + lessonId, lastAccessedAt, completedAt

Do not add Assessment, Question, Attendance, GradeRecord, Notification, or AuditLog models.

Seed (packages/database/prisma/seed.ts), Grade 10 Mathematics / 10A:

  • One unit
  • Three lessons: rich text, external link, PDF (MinIO object or inline placeholder)
  • Two published assignments (one due soon, one later)
  • Timetable slots that include a period on “today”
  • Optional in-progress lesson so Continue Learning is non-empty

Verify: pnpm db:seed produces queryable units, lessons, timetable slots, and published assignments for 10A Mathematics.

Slice 1 — Student APIs + storage

Goal: student-scoped REST under /api/v1/me. Role STUDENT + existing TenantGuard. Scope by enrollment — a student cannot read another class’s content or another school’s rows.

Module: apps/api/src/modules/student/. DTOs in packages/validation; types in packages/types. List/single/error envelopes from API Design.

Key endpoints:

GET  /api/v1/me
GET  /api/v1/me/dashboard
GET  /api/v1/me/subjects
GET  /api/v1/me/subjects/:id
GET  /api/v1/me/lessons/:id
POST /api/v1/me/lessons/:id/progress     { completed?: boolean }
GET  /api/v1/me/assignments
GET  /api/v1/me/assignments/:id
POST /api/v1/me/files/presign            { purpose, mimeType, size }
POST /api/v1/me/assignments/:id/draft    { storageKey }
POST /api/v1/me/assignments/:id/submit

Storage: extend StorageService with presigned upload. Keys:

{schoolId}/submissions/{assignmentId}/{studentId}/{uuid}.{ext}
{schoolId}/materials/{subjectId}/{lessonId}/{uuid}.{ext}

MIME type and file size limits on presign. Never public buckets. DB stores storageKey, mimeType, size, checksum — not file bytes.

Tests: enrollment isolation; submit → status SUBMITTED (or LATE after due date).

Verify: authenticated student can load dashboard payload and submit an assignment; a user from another school cannot.

Slice 2 — Dashboard

Route: /student/dashboard in apps/web. Replace PlaceholderPage.

UI: HeroUI v3 (heroui-react skill) — Card, Skeleton, Alert. TanStack Query + existing apiFetch. Copy under student.* in EN and AR.

  • Header: time-of-day greeting + givenName (e.g. “Good morning, Omar”)
  • Today’s schedule from TimetableSlot
  • Upcoming: assignments only (no quizzes)
  • Continue learning: last LessonProgress
  • Overview: assignment completion count only — not GPA or attendance

Verify: after login as student, dashboard shows schedule and upcoming work.

Slice 3 — Classes + subject page

Routes:

  • /student/classes — enrolled subjects (class + teaching assignments)
  • /student/classes/:subjectId — teacher name, units, lessons, materials, assignments, progress %

Nested routes in App.tsx. Breadcrumbs: role → My Classes → subject. Wire AppShell current item so nested subject URLs still highlight My Classes.

Verify: student can browse enrolled subjects and open Grade 10 Mathematics.

Slice 4 — Lesson viewer + progress

Route: /student/classes/:subjectId/lessons/:lessonId

Content pane + unit/lesson sidebar. RTL-safe (sidebar follows dir).

Render by type: rich text/HTML, video URL, PDF (presigned GET), image, external link.

On open: upsert LessonProgress.lastAccessedAt. Complete control sets completedAt.

Verify: student can open a lesson; progress persists after reload.

Slice 5 — Assignments

Routes:

  • /student/assignments — list with status + due date
  • /student/assignments/:id — instructions, due date, resources, upload/replace before deadline, submit

Status chips: Not started / Draft / Submitted / Late. Do not show grade or feedback UI (Phase 4).

After submit, status is Submitted (or Late). Success confirmation — HeroUI Toast or inline success per UX States.

Verify: upload + submit updates status to Submitted.

Slice 6 — UX + mobile

Apply on every new screen: Skeleton loading, empty copy, Alert + retry, submit success. No blank screens.

Mobile bottom nav and pb-24 already exist in AppShell — verify they still work with nested lesson/assignment URLs (parent nav item active).

/student/grades stays a later-phase placeholder (app.comingSoon or equivalent).

Verify: no blank screens; mobile nav works; EN/AR + RTL; light and dark themes.
