Companion to Phase 6 — Administration (scope guards and acceptance criteria). This page is the execution plan: API gaps, admin-only endpoints, apps/web screens, and apps/system-admin (Slices 8–9). Slice 1 is the API prerequisite; later slices map to the phase index.

School admin plus operator console. Notifications and announcements are Phase 7. No GPA, grading-scheme admin, audit UI, school logo, billing, impersonation, or School.status. Do not add /api/v1/grades for marks — academic GET /grades is the year-level resource. SYSTEM_ADMIN does not manage school academics.

Slice order

Slice 1 first (APIs). Then dashboard → people → academics → assign/enroll → search/reports/settings. Sequential; each slice is independently verifiable. Slice 7 completes the school dashboard. Slices 8–9 finish the Phase 1c operator console. Slice 10 adds configurable academic terms.

In scope

  • Admin dashboard: school overview, academic overview with filters, operational attention lists
  • People: searchable student and teacher tables; view/edit/create/deactivate
  • Academic structure UI: years, terms, grades, classes, subjects (2–4 configurable terms per year; classes stay year-long)
  • Enroll students in classes; assign teachers to class + subject; remove both
  • Basic analytics on Reports (same metrics, filterable)
  • School settings: name and default locale; slug read-only
  • Global search across students, teachers, classes, subjects, lessons, assignments
  • EN/AR + RTL; loading / empty / error / success per UX States
  • System-admin console: platform overview, school tenant list/create/edit (name, slug, locale), System health (API, DB, Redis)

Out of scope

  • Notifications, BullMQ, announcements
  • Audit log UI / pipeline
  • Billing, impersonation, School.status, deleting schools
  • GPA, grading schemes, course CMS, permissions matrix, school logo
  • Per-term enrollment, report cards, nesting classes under terms, holiday calendar
  • Per-subject student enrollment; teacher “department”
  • Student-facing attendance view
  • apps/mobile-staff, Elasticsearch

Locked API shape

Reuse Phase 2 domain routes for CRUD. Do not duplicate /admin/students CRUD. New admin-only resources: overview, search, school settings.

  • Extend: GET /students, GET /teachers with q, status, class filters and richer payloads; PATCH status; DELETE enrollments and teaching assignments
  • Admin: GET /api/v1/admin/overview (optional year/grade/class/subject/teacher filters; includes activeCourses and attention lists)
  • Search: GET /api/v1/search?q=
  • School: GET/PATCH /api/v1/school — name and locale; slug read-only
  • Platform (SYSTEM_ADMIN, no tenant guard): GET /api/v1/platform/overview, GET/POST /api/v1/platform/schools, PATCH /api/v1/platform/schools/:id; public GET /api/v1/health reports API + DB + Redis
  • Terms: GET/POST /api/v1/academic-years/:id/terms, PATCH/DELETE /api/v1/terms/:id

Deactivate sets User.status to disabled. Admin cannot deactivate self. Average on the student table is the mean of GradeRecord.percentage, or empty if none.

Slice 0 — This plan

Goal: lock execution. No schema migration required.

Verify: this page is linked from the Phase 6 index.

Slice 1 — APIs

Modules: extend apps/api/src/modules/academic/; expand admin/; add search + school controllers. Isolation tests for tenant scope, role gates, unenroll, and deactivate.

Verify: student token cannot read overview; second-school token cannot see EIS students; unenroll persists.

Slice 2 — Dashboard

Route: /admin/dashboard. School-wide cards: students, teachers, classes, subjects, attendance %, assignment completion %, performance %. Link into Reports.

Verify: admin@nabta.local sees Egyptian International School counts.

Slice 3 — People UI

Routes: /admin/users (Students / Teachers tabs), /admin/users/students/:id, /admin/users/teachers/:id.

Searchable tables. Create/edit dialogs. Deactivate with confirm. Student columns: name, class, grade, attendance, average, status. Teacher columns: name, email, classes, subjects, status.

Verify: admin can create, edit, search, and deactivate a student without deleting them.

Slice 4 — Academic structure UI

Route: /admin/academics. CRUD years, terms, grades, classes, subjects (subjects stay configurable). Terms are periods on the year; classes remain year-long.

Verify: admin can add a class or subject without breaking seeded 10A Mathematics.

Slice 5 — Assign / enroll

Enroll student ↔ class; teaching assignment teacher ↔ class + subject; remove both. From profile pages and /admin/academics/classes/:id.

Verify: assign a teacher/student and see the row on the class hub.

Slice 6 — Search, reports, settings

Command search in the admin shell. Reports = overview metrics with filters. Settings save name and locale. /admin redirects to dashboard.

Verify: login → academics → assign → search finds the person → settings save locale.

Slice 7 — Dashboard complete

Route: /admin/dashboard (not apps/system-admin). School overview (unfiltered eight cards including active courses) plus in-page academic overview with the same year / grade / class / subject / teacher filters as Reports. Attention lists: unenrolled students, classes without a teacher, teachers without an assignment. Shared metric/filter UI with Reports.

GET /admin/overview also returns activeCourses (teaching-assignment count) and attention item lists (cap 5) with web hrefs.

Verify: admin@nabta.local on http://localhost:5173/admin/dashboard sees Egyptian International School name, counts, academic filters, and attention lists — never later-phases copy.

Slice 8 — Platform APIs

Modules: expand apps/api/src/modules/platform/ into a module + service. JwtAuthGuard + SYSTEM_ADMIN only — no TenantGuard. Keep GET /platform/ping.

  • GET /api/v1/platform/overview — school / student / teacher / school-admin counts, health snapshot, school preview (cap 5)
  • GET /api/v1/platform/schools — all tenants with student and teacher counts
  • POST /api/v1/platform/schools — name, unique kebab-case slug, locale. Does not provision an ADMIN user
  • PATCH /api/v1/platform/schools/:id — name and locale; slug read-only. No delete
  • GET /api/v1/health — API + Postgres + Redis (ok / down); HTTP 200 even if degraded

Verify: school ADMIN token is 403 on platform routes; unique slug persists; health reports mocked DB/Redis.

Slice 9 — Operator UI

App: apps/system-admin on port 5175. Replace Overview, Schools, and System placeholders. No later-phases copy. HeroUI v3 cards and modals; local loading/error/empty states.

  • Overview: metric cards (schools → /schools, health → /system) and school preview
  • Schools: table, create (name, slug, locale), edit name/locale
  • System: API / database / Redis from GET /health

Verify: system@nabta.local on http://localhost:5175 sees Egyptian International School, can create/edit a tenant, and sees DB/Redis status — never later-phases copy. School admin on 5173 is unchanged.

Slice 10 — Academic terms

Prisma Term (schoolId, academicYearId, name, startsOn, endsOn, sortOrder). Configurable 2–4 terms per year. Do not nest Class under Term. Do not attach termId to assignments, attendance, or grade records in this slice.

  • GET/POST /api/v1/academic-years/:id/terms
  • PATCH/DELETE /api/v1/terms/:id
  • Academics UI lists terms under the year; seed Term 1–3 on EIS 2026/2027

Verify: admin@nabta.local sees Term 1–3 under the year and can add/edit dates without moving 10A under a term.
