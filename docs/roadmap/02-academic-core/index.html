Phase 2 — Academic Core

Phase 2 Complete Historical specification — do not re-implement unless fixing regressions.

Status: Complete — academic hierarchy APIs with tenant isolation, Egyptian International School seed (2026/2027, Grades 7–12), one-page marketing landing (Namya Khan) with on-page demo form. Next: Phase 3 — Student Experience (complete) · Phase 4 — Teacher Experience (complete) · Phase 5 — Assessments (current).

Depends On

  • Phase 1 — Foundation Complete
  • Phase 1b — Marketing Site Bootstrap
  • Phase 1c — System Admin Bootstrap
  • Phase 1d — Mobile Student Bootstrap
  • Phase 1e — Mobile Staff Bootstrap

Goal

Implement the core academic domain: schools, academic years, grades, classes, subjects, students, teachers, enrollments, and teaching assignments. In parallel, polish the marketing home page to a high-converting SaaS landing layout.

In Scope

  • School entity with multi-tenancy (schoolId)
  • Academic years, grades, classes, subjects (CRUD)
  • Student and teacher profiles linked to users
  • Enrollments (student → class)
  • Teaching assignments (teacher → subject/class)
  • Seed data: Egyptian International School, 2026/2027, Grades 7–12
  • API endpoints for all academic entities
  • Marketing home polish (Namya Khan landing anatomy) in apps/marketing
  • Contact/demo form backend (POST /api/v1/marketing/contact)

Out of Scope

  • Student/teacher portal UIs (dashboards, lessons) — Phase 3 / 4
  • Assignments, assessments, attendance — Phase 5
  • Admin dashboard analytics — Phase 6
  • Notifications — Phase 7
  • Marketing production deploy — remains Phase 1b Remaining

Acceptance Criteria

  • Admin can create academic year → grade → class → subject hierarchy via API
  • Students can be enrolled in classes
  • Teachers can be assigned to subjects/classes
  • All entities scoped by schoolId with tenant isolation enforced
  • Seed script populates realistic demo data
  • Subject lists are configurable, not hardcoded
  • All relationships persist to PostgreSQL
  • Marketing home renders navbar, hero, benefits, how it works, testimonials, pricing, FAQ, contact form, and footer
  • New marketing copy works in EN and AR with RTL
  • Light and dark themes apply to all home sections
  • Navbar and CTAs scroll to in-page sections (#features, #for-schools, #pricing, #contact); contact form submits to the API

Implementation slices

Derived from this phase’s acceptance criteria. Slices 1–5 are sequential (Academic Core). Slice 6 (marketing) may run in parallel. Do not implement Phase 3+. Full detail: detailed plan.

  1. School tenant — school entity with schoolId scoping. Verify: tenant isolation is enforced on academic entities.
  2. Hierarchy APIs — CRUD for academic year → grade → class → subject. Verify: an admin can create the full hierarchy via API.
  3. People + assignments — student and teacher profiles; enrollments (student → class); teaching assignments (teacher → subject/class). Verify: enrollments and assignments persist to PostgreSQL.
  4. Configurable subjects — subject lists are data, not hardcoded. Verify: subjects can be created without code changes.
  5. Demo seed — Egyptian International School, 2026/2027, Grades 7–12. Verify: seed script populates realistic demo data.
  6. Marketing home polish — Namya Khan anatomy as a one-page site with section nav; contact form on-page → API. Verify: sections render; hash nav; EN/AR + themes; form works.
