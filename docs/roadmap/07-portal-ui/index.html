Phase 7 — Portal UI

Phase 7 Current Implement this phase only. Do not implement Phase 8+ functionality.

Current phase. Phase 6 Administration is complete. Polish the shipped web portals in order — student, teacher, school admin, system admin. Student execution plan: student portal polish plan. Teacher and later portals wait.

Goal

Raise the visual and interaction quality of existing web portals so they feel consistent, calm, and production-ready — HeroUI v3, UX States, EN/AR and RTL — without adding product features.

In Scope

  • Student portal UI polish
  • Teacher portal UI polish
  • School admin portal UI polish
  • System admin console UI polish

Out of Scope

  • New product features
  • Notifications, BullMQ, announcements (Phase 8)
  • Marketing site
  • Mobile apps (apps/mobile-student, apps/mobile-staff)

Acceptance Criteria

  • Each portal is polished in order; later portals are not started until the prior plan is done
  • Screens keep loading, empty, error, and success states
  • EN/AR and RTL remain correct after layout changes
  • No new domain APIs or schema for this phase

Implementation slices

Complete in order. Each slice is independently verifiable. A detailed execution plan is added per portal when that slice starts — do not invent parallel polish work. Do not implement Phase 8+.

  1. Student — apps/web student routes. Execution: student portal polish plan. Verify: student flows look and behave consistently with the design system.
  2. Teacher — teacher routes. Plan after student ships.
  3. School admin — admin routes. Plan after teacher ships.
  4. System admin — apps/system-admin. Plan after school admin ships.
