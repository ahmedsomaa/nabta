Phase 7 — Student portal polish plan

Phase 7 Current Execution plan for the student web portal only. Raise visual hierarchy with semantic color, card grids, and icons — without new features or APIs.

Companion to Phase 7 — Portal UI. Teacher, school admin, and system admin polish wait until this student plan ships. Do not implement Phase 8+.

Web student portal only. No new routes, GPA, attendance, announcements, profile, or notification center. No rainbow subject palettes. Reuse existing /me endpoints. Demo: student@nabta.local / Password123! at http://localhost:5173/student/dashboard.

Slice order

Shared primitives first, then screens in student-nav order. Sequential; each slice is independently verifiable.

Visual direction

  • Calm academic richness — not neon, gamification, or a second brand color
  • Color via tokens only: --accent / bg-accent/10, --warning, --danger, --success
  • Subject identity: Lucide icon well + initials avatar, not a unique hue per class
  • Static Lucide on content; lucide-animated only on empty states and the Continue learning hover CTA
  • HeroUI v3: ProgressBar, ProgressCircle, Avatar, Chip, RadioGroup, Checkbox, Surface, layout-shaped Skeleton

Original agent prompt

Implement Phase 7 student portal polish only per docs/roadmap/07-portal-ui/plan.html.
Do not implement teacher/admin polish or Phase 8+ functionality.

In scope

  • apps/web student routes: dashboard, classes, subject, lesson, assignments, assessments, grades
  • Shared student primitives: page header, empty state, icon well, work item card, skeleton variants
  • EN/AR + RTL; loading / empty / error / success per UX States

Out of scope

  • Teacher, school admin, system admin polish
  • Notifications, BullMQ, announcements
  • New domain APIs or schema
  • Marketing site, mobile apps
  • GPA, attendance, profile, More nav

No API changes

Reuse existing student endpoints only: GET /me, GET /me/dashboard, GET /me/subjects, subject/lesson/assignment/assessment/grades routes already shipped in Phases 3 and 5.

Slice 0 — This plan

Goal: lock student polish execution.

Verify: this page is linked from the Phase 7 index.

Slice 1 — Shared primitives and icons

Goal: student-only building blocks and a small lucide-animated set.

Files: apps/web/src/features/student/, apps/web/src/components/icons/, packages/i18n/locales/.

UI: StudentPageHeader, StudentEmptyState, IconWell, WorkItemCard, HeroUI ProgressBar, layout-shaped skeletons. Keep EmptyCard working for teacher/admin if they still import it.

Verify: components render in isolation; teacher pages that import QueryState still compile.

Slice 2 — Dashboard

Goal: “what should I do today?” with greeting strip, 2×2 metric tiles, clickable schedule, upcoming cards, continue-learning.

Route: /student/dashboard.

Verify: student@nabta.local sees greeting, metrics from existing dashboard/grades payloads, schedule links to a subject, upcoming uses status color, continue-learning shows a progress bar.

Slice 3 — Classes and subject

Goal: richer class tiles and a subject header with a real progress bar and lesson type icons.

Routes: /student/classes, /student/classes/:subjectId.

Verify: class grid is 2–3 columns on desktop; subject lessons show type icons from existing lesson payload.

Slice 4 — Lesson

Goal: type chip, prev/next from the unit list already loaded, completion chip.

Route: /student/classes/:subjectId/lessons/:lessonId.

Verify: media embeds still work; prev/next move within the unit when siblings exist.

Slice 5 — Assignments

Goal: list grouped by overdue / due soon / rest; detail upload as a dashed surface with file icons.

Routes: /student/assignments, /student/assignments/:id.

Verify: grouping uses existing due dates; submit/toast/lock behavior unchanged.

Slice 6 — Assessments

Goal: overview chips; attempt uses HeroUI radios/checkboxes, sticky timer, n of N; result uses a score visualization.

Routes: assessment overview, attempt, result.

Verify: start/resume/submit still hit the same APIs; MCQ selection looks like the rest of the portal.

Slice 7 — Grades

Goal: metric tiles + letter chips on the list; detail uses a meter/progress for current %.

Routes: /student/grades, /student/grades/:subjectId.

Verify: table still lists subjects; letter chips use success/warning/danger; no GPA invented.

Slice 8 — RTL, dark, mobile

Goal: pass every student route in EN/AR, light/dark, and ~375px.

Verify: logical CSS; empty/loading/error still work; teacher/admin not visually broken by shared QueryState changes.

Acceptance (phase index)

  • Student portal is polished; teacher/admin/system-admin not started from this plan
  • Screens keep loading, empty, error, and success states
  • EN/AR and RTL remain correct
  • No new domain APIs or schema
