Cursor Working Rules

  1. Inspect the existing project structure before implementing
  2. Reuse existing abstractions — do not duplicate components
  3. Do not introduce new libraries unless necessary
  4. Follow existing naming conventions
  5. Check related backend modules before changing database models
  6. Check existing frontend components before creating new ones
  7. Keep changes focused — do not rewrite unrelated code
  8. When functionality is in the UI, it must work or be marked as not yet implemented
  9. Prioritize correctness and architecture over number of screens generated
