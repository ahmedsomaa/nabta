Getting Started

How to use the Nabta documentation to build the platform incrementally.

Golden rule: Implement one phase folder at a time. Phases 1–3 are Complete. Start with Phase 4 — Teacher Experience. Do not implement Phase 5+ while working on Phase 4.

Documentation Structure

SectionPurpose
BusinessWhy Nabta exists — positioning, vision, glossary
RequirementsWhat Nabta must do — product behavior by portal and platform topic
DesignHow it should look — colors, typography, logos, UX states
TechnicalHow it is built — stack, deployment, diagrams
RoadmapWhen to build what — one phase folder at a time

Recommended Workflow

  1. Read the current phase folder — Phase 4 — Teacher Experience
  2. Review linked requirement, design, and technical pages
  3. Give Cursor a focused prompt: "Implement Phase 4 only. Do not implement Phase 5+ functionality."
  4. Verify acceptance criteria on the phase page
  5. Move to the next phase when complete

Local Development

Prerequisites: Node.js 22+, pnpm 10+, Docker Desktop (Postgres, Redis, MinIO).

pnpm install
cp .env.example .env
pnpm docker:up
pnpm db:generate
pnpm db:migrate
pnpm db:seed

Database URL is configured in packages/database/prisma.config.ts (reads the monorepo root .env). After schema changes, run pnpm db:generate before starting apps.

Start the four browser/API apps (no mobile):

pnpm start:web

pnpm start:webAPI + web + marketing + system-admin3000, 5173, 5174, 5175

Cursor Working Rules

  • Inspect the existing project structure before implementing
  • Reuse existing abstractions — do not duplicate components
  • Follow existing naming conventions
  • Keep changes focused — do not rewrite unrelated code
  • When functionality is in the UI, it must work or be marked as not yet implemented
  • Prioritize correctness and architecture over number of screens generated
