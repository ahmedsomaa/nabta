Critical E2E Workflows (Phase 3+)

  • Student: Login → Dashboard → Subject → Lesson → Assignment → Submit
  • Teacher: Login → Class → Assignment → Grade submission
  • Admin: Login → Users → Student → Update academic assignment

CI/CD Pipeline — GitHub Actions

Established in Phase 1. All workflows in .github/workflows/.

flowchart LR
  push[Push or PR] --> lint[Lint + Typecheck]
  lint --> test[Unit + Integration Tests]
  test --> build[Build Apps]
  build --> docker[Build Docker Images]
  docker --> deploy[Deploy Preview or Staging]

PR Workflow

  • Lint (ESLint) + typecheck (tsc)
  • Run unit and integration tests
  • Build all apps
  • Block merge on failure

Main Branch Workflow

  • All PR checks
  • Build and push Docker images to GHCR
  • Deploy to staging (Render/Fly + Neon + Upstash)

Release Workflow

  • Triggered on tagged release
  • Promote staging image to production (manual approval gate initially)

Workflow Files

.github/workflows/
├── ci.yml           # PR: lint, test, build
├── deploy-staging.yml   # main: deploy to staging
└── deploy-prod.yml      # release tag: deploy to production

Test Database

  • Integration tests use a separate test database (Docker Compose test profile or ephemeral DB)
  • Each test suite resets/migrates schema before running
  • Never run tests against development or production databases

Acceptance Criteria (Phase 1)

  • GitHub Actions CI runs on every PR
  • At least one API unit test and one integration test pass
  • At least one web component test passes
  • Failed CI blocks merge
  • Docker images build successfully in CI
