Email (Resend)

Backend transactional email via Resend — auth emails in Phase 1, notification emails in Phase 7.

Architecture

EmailService (interface)
  └── ResendEmailService (default)
        ├── auth emails (Phase 1)
        └── notification emails (Phase 7)

EmailService Interface

interface EmailService {
  send(params: {
    to: string;
    subject: string;
    html: string;
    templateId?: string;
  }): Promise<void>;
}

Business logic uses the interface, not Resend directly. This allows swapping providers without changing domain modules.

Resend Integration

ItemDetail
Packageresend in apps/api
Moduleapps/api/src/modules/email/
Templatesapps/api/src/modules/email/templates/ (HTML or React Email)
Env varsRESEND_API_KEY, RESEND_FROM_EMAIL (e.g. noreply@nabta.app)
SecretsStored in deployment secrets — not in Docker Compose or git

Phase 1 — Auth Emails (Implement)

  • Password reset — link with expiring token
  • Welcome / email verification — if email verification is enabled

Templates support EN and AR based on user locale preference.

Phase 7 — Notification Emails (Implement)

  • Assignment created / due soon / graded
  • New announcement
  • Grade published

Sent asynchronously via BullMQ worker after in-app notification is created. User email preferences respected.

Pipeline

flowchart LR
  Event[DomainEvent] --> Queue[BullMQ]
  Queue --> Worker[NotificationWorker]
  Worker --> DB[(InAppNotification)]
  Worker --> Email[ResendEmailService]
  Email --> Resend[Resend API]

Password Reset Flow

sequenceDiagram
  participant User
  participant API as NestJS API
  participant Resend as Resend API
  User->>API: POST /api/v1/auth/forgot-password {email}
  API->>API: Generate reset token
  API->>Resend: send password-reset template
  Resend-->>User: Email with reset link
  User->>API: POST /api/v1/auth/reset-password {token, password}
  API->>API: Validate token, update password

Rules

  • Never log email content containing tokens or PII
  • Rate limit forgot-password endpoint
  • Do not reveal whether an email exists in the system
  • EN/AR templates where user locale is known
  • Resend API key only in server environment — never in frontend

Acceptance Criteria

  • EmailService interface with ResendEmailService implementation
  • RESEND_API_KEY and RESEND_FROM_EMAIL in .env.example
  • Password reset email sends successfully in Phase 1
  • Notification emails send via Resend in Phase 7
  • Templates available in EN and AR
