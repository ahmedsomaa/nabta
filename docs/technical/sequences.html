Sequence Diagrams

Major application flows as sequence diagrams.

1. Login & Refresh Token Session

sequenceDiagram
  participant Browser
  participant API as NestJS API
  participant DB as PostgreSQL
  Browser->>API: POST /api/v1/auth/login {email, password}
  API->>DB: Find user by email
  DB-->>API: User record
  API->>API: Verify password hash
  API->>API: Generate JWT + refresh token
  API-->>Browser: {accessToken, refreshToken, user}
  Note over Browser: Store tokens, redirect to dashboard
  Browser->>API: GET /api/v1/students/me (Bearer JWT)
  API->>API: JwtAuthGuard validates token
  API->>DB: Query with schoolId from JWT
  DB-->>API: Student data
  API-->>Browser: {data: student}

2. Admin Academic Setup

sequenceDiagram
  participant Admin
  participant API as NestJS API
  participant DB as PostgreSQL
  Admin->>API: POST /api/v1/academic-years {name: 2026/2027}
  API->>DB: Create AcademicYear (schoolId from JWT)
  API-->>Admin: {data: academicYear}
  Admin->>API: POST /api/v1/grades {name: Grade 10, yearId}
  API->>DB: Create Grade
  Admin->>API: POST /api/v1/classes {name: 10A, gradeId}
  API->>DB: Create Class
  Admin->>API: POST /api/v1/subjects {name: Physics}
  API->>DB: Create Subject
  Admin->>API: POST /api/v1/teaching-assignments {teacherId, subjectId, classId}
  API->>DB: Create TeachingAssignment
  Admin->>API: POST /api/v1/enrollments {studentId, classId}
  API->>DB: Create Enrollment
  API-->>Admin: All relationships persisted

3. Assignment Workflow

sequenceDiagram
  participant Teacher
  participant Student
  participant API as NestJS API
  participant Queue as BullMQ
  participant DB as PostgreSQL
  Teacher->>API: POST /api/v1/assignments {title, dueDate, subjectId}
  API->>DB: Create Assignment
  API->>Queue: Enqueue assignment_created event
  API-->>Teacher: {data: assignment}
  Queue->>DB: Create Notifications for enrolled students
  Student->>API: GET /api/v1/notifications
  API-->>Student: New assignment notification
  Student->>API: POST /api/v1/assignments/:id/submit {file}
  API->>DB: Create AssignmentSubmission (status: Submitted)
  API-->>Student: {data: submission}
  Teacher->>API: GET /api/v1/assignments/:id/submissions
  API-->>Teacher: List of submissions
  Teacher->>API: PATCH /api/v1/submissions/:id {grade, feedback}
  API->>DB: Update submission (status: Graded)
  API->>Queue: Enqueue assignment_graded event
  Queue->>DB: Create Notification for student
  Student->>API: GET /api/v1/assignments/:id
  API-->>Student: {grade, feedback, status: Graded}

4. Student Takes Assessment

sequenceDiagram
  participant Student
  participant API as NestJS API
  participant DB as PostgreSQL
  Student->>API: GET /api/v1/assessments/:id
  API-->>Student: Assessment overview (time limit, attempts)
  Student->>API: POST /api/v1/assessments/:id/start
  API->>DB: Create AssessmentAttempt
  API-->>Student: {attemptId, questions}
  loop Each question
    Student->>API: PATCH /api/v1/attempts/:id/answers {questionId, answer}
    API->>DB: Save answer
  end
  Student->>API: POST /api/v1/attempts/:id/submit
  API->>API: Auto-score objective questions
  API->>DB: Update attempt (score, status: completed)
  API-->>Student: {score, feedback, passed}

5. Teacher Records Attendance

sequenceDiagram
  participant Teacher
  participant API as NestJS API
  participant DB as PostgreSQL
  Teacher->>API: GET /api/v1/classes/:id/students
  API-->>Teacher: Student list for class
  Teacher->>API: POST /api/v1/attendance {classId, date, records: [{studentId, status}]}
  API->>API: RolesGuard checks TEACHER role
  API->>API: TenantGuard scopes to schoolId
  API->>DB: Bulk create/update Attendance records
  API-->>Teacher: {data: attendanceSession}
  Note over Teacher: Student can later view attendance via GET /api/v1/attendance/me

6. Tenant Isolation on Authorized Request

sequenceDiagram
  participant Client
  participant Guard as JwtAuthGuard
  participant Tenant as TenantGuard
  participant Service as Domain Service
  participant DB as PostgreSQL
  Client->>Guard: Request with JWT (schoolId: A)
  Guard->>Guard: Validate JWT, extract user context
  Note over Guard: schoolId = A (from JWT, NOT from request body)
  Guard->>Tenant: Pass authenticated user
  Tenant->>Tenant: Verify resource belongs to schoolId A
  Tenant->>Service: Authorized request
  Service->>DB: Query WHERE schoolId = A
  DB-->>Service: Only School A data
  Service-->>Client: Response
  Note over Client: User from School B cannot access School A data even with manipulated IDs

7. Notification Job Path

sequenceDiagram
  participant API as NestJS API
  participant Redis as Redis/BullMQ
  participant Worker as Notification Worker
  participant DB as PostgreSQL
  participant Resend as Resend API
  API->>API: Domain event (e.g. assignment graded)
  API->>Redis: Enqueue job {type, userId, payload}
  API-->>API: Continue (non-blocking)
  Redis->>Worker: Pick up job
  Worker->>DB: Create Notification record
  Worker->>Worker: Check email preferences
  Worker->>Resend: EmailService.send (Resend)
  Note over Resend: Assignment, announcement, grade emails
  Note over DB: Student sees notification on next GET /api/v1/notifications
