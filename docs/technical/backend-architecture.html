Module Pattern

Each domain module owns:

  • Controller — HTTP routing, request/response mapping only
  • Service — Business logic and domain rules
  • DTOs — Input validation with class-validator
  • Module — Dependency injection wiring

Do not put business logic in controllers. Do not create a monolithic app.service.ts.

Guards & Decorators

Guard/DecoratorPurpose
JwtAuthGuardValidates JWT, attaches user to request
RolesGuardChecks user role (STUDENT, TEACHER, ADMIN)
TenantGuardEnsures schoolId scoping on queries
@CurrentUser()Extracts authenticated user from request
@Roles('TEACHER')Restricts endpoint to specific roles

Database Access

  • Prisma client from packages/database
  • All queries scoped by schoolId from authenticated user
  • Use Prisma include and select to avoid N+1 queries
  • Pagination via skip/take with total count

Background Jobs

  • BullMQ processors in notifications module
  • Jobs enqueued from domain services on events
  • Workers create notification records and send emails via ResendEmailService

Email Module

Transactional email via Resend. Env vars: RESEND_API_KEY, RESEND_FROM_EMAIL (e.g. noreply@nabta.app).

  • EmailService interface — domain modules depend on the interface, not Resend directly
  • ResendEmailService — default implementation in apps/api/src/modules/email/
  • Phase 1: password reset, welcome/verification emails
  • Phase 7: notification emails (assignment, announcement, grade events)
