API Design

Versioned REST API conventions, response format, and validation.

Base URL

/api/v1/

Endpoints

/api/v1/auth          # login, register, refresh, logout
/api/v1/academic-years               # year CRUD
/api/v1/academic-years/:id/terms     # list/create terms on a year
/api/v1/terms/:id                    # PATCH/DELETE a term
/api/v1/students      # student CRUD, enrollments
/api/v1/teachers      # teacher CRUD, assignments
/api/v1/classes       # class CRUD, students
/api/v1/subjects      # subject CRUD, lessons, materials
/api/v1/assignments   # assignment CRUD, submissions
/api/v1/teacher/assessments  # teacher quiz CRUD, publish, results
/api/v1/me/assessments       # student overview + start
/api/v1/me/attempts          # answer, submit, result
/api/v1/me/grades            # subject GradeRecord list + drill-down
/api/v1/grades        # year-level Grade 7–12 (not marks)
/api/v1/attendance    # attendance records
/api/v1/admin/overview       # school + academic metrics, attention lists
/api/v1/search               # global search (q=)
/api/v1/school               # GET/PATCH school name + locale (slug read-only)
/api/v1/platform/overview    # SYSTEM_ADMIN — tenant counts + health snapshot
/api/v1/platform/schools     # SYSTEM_ADMIN — list/create; PATCH /:id (no delete)
/api/v1/health               # public — API + Postgres + Redis (ok/down)
/api/v1/announcements # announcements (Phase 8)
/api/v1/notifications # user notifications (Phase 8)

School-scoped routes use JWT schoolId and TenantGuard. Platform routes require SYSTEM_ADMIN and skip the tenant guard. GET /health is public and returns HTTP 200 even when a dependency is down.

Response Format

Success (list)

{
  "data": [ ... ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 120
  }
}

Success (single)

{
  "data": { ... }
}

Error

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable message",
    "details": [ ... ]
  }
}

Conventions

  • Pagination: ?page=1&limit=20
  • Filtering: ?grade=10&status=active
  • Sorting: ?sort=createdAt&order=desc
  • IDs: UUIDs in URLs, never sequential database IDs
  • Auth: Bearer JWT in Authorization header

Validation

  • NestJS ValidationPipe on all DTOs
  • Shared Zod schemas in packages/validation (used by frontend too)
  • Reject invalid input with 400 and structured error response

Security

  • All endpoints (except auth) require valid JWT
  • RBAC guards on role-restricted endpoints
  • schoolId derived from JWT, never from request body/params
  • Rate limiting on auth endpoints
