Web vs Native HeroUI

  • Web (apps/web, apps/marketing, apps/system-admin): HeroUI v3 on React Aria + Tailwind CSS v4. Theme via CSS variable overrides (oklch) — see Theming.
  • Native (apps/mobile-student, apps/mobile-staff): HeroUI Native on Uniwind. Theme via HSL semantic tokens aligned to Nabta green intent — see Theming — Native.
  • Do not mix libraries — web apps use @heroui/react; mobile apps use heroui-native. Share business logic via packages/types, packages/validation, and packages/i18n.
  • Agent skills: heroui-react for web; heroui-native for mobile.

Providers (App Shell)

  • ThemeProvider — light/dark mode with persisted preference
  • I18nProvider — react-i18next with EN/AR, RTL via dir attribute
  • QueryClientProvider — TanStack Query
  • AuthProvider — current user + tokens

Component Library

HeroUI v3 (@heroui/react + @heroui/styles) on React Aria + Tailwind CSS v4. Import Tailwind first, then @heroui/styles. Prefer compound components; use onPress over onClick; use className (not v2 classNames). No HeroUI Provider required in v3. Theme Nabta via CSS variable overrides — see Theming.

HeroUI is for controls. Lists, detail panels, and tiles use a 1px bordered shell — see Portal Patterns. Do not wrap queues in HeroUI Card.

Icons

  • Default: lucide-react for static icons (nav, forms, tables)
  • Selective: lucide-animated only where motion helps affordance — import from @/components/icons/...
  • Install per icon via shadcn registry CLI (npx shadcn@latest add "https://lucide-animated.com/r/<name>.json"); do not animate every icon
  • Brand mark (Sprout) stays a static Lucide path — see Logos

Internationalization

  • Translations from packages/i18n (en.json, ar.json)
  • Locale switcher in app shell header
  • RTL: set dir="rtl" on <html> when Arabic active
  • Use logical CSS properties (ms-, me-, ps-, pe-)

Theme (Light / Dark)

  • HeroUI CSS variables; Nabta --accent = #10B981 — see Colors and Theming
  • Theme toggle in app shell; persist in localStorage/profile
  • Respect prefers-color-scheme as default

State Management

  • Server state: TanStack Query — all API data fetched, cached, and invalidated via queries/mutations
  • UI state: Local component state (useState, useReducer)
  • Auth state: Context or Zustand for current user + tokens
  • Do not duplicate server data in global state unnecessarily

Rules

  • No business logic in React components — use hooks and services
  • Use HeroUI components; don't reinvent primitives
  • Prefer Lucide React; use lucide-animated sparingly for interactive affordances
  • Lazy-load routes for code splitting
  • Every feature has loading (skeleton), empty, error, and success states
  • Use shared Zod schemas from packages/validation for forms
