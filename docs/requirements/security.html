Security

Academic systems require traceability, tenant isolation, and defense-in-depth.

Authentication

  • Email/password initially
  • Refresh tokens, secure password hashing
  • Account status, session management, logout
  • Password reset sends via Resend (Phase 1)
  • SSO-ready (Microsoft Entra ID, Google Workspace, Microsoft 365) — not required in v1

Authorization

  • RBAC with centralized guards/decorators
  • Backend enforces — frontend only hides UI
  • Never trust client-provided schoolId, userId, role, permissions
  • Derive authorization context from authenticated user
  • Protection against IDOR (Insecure Direct Object Reference)

Tenant Isolation

All school-owned entities scoped by schoolId. Backend enforces — user from School A must never access School B data.

Input & Output Security

  • Input validation (DTOs, Zod, ValidationPipe)
  • Rate limiting
  • Secure file uploads with type validation
  • SQL injection protection through Prisma
  • XSS-safe rendering
  • CSRF strategy where applicable

Audit Logging

Track important actions with: Who, What, When, Entity, Entity ID, Before, After, IP/metadata.

Examples: grade changed, student status changed, assignment deleted, teacher assigned, attendance modified.

Do not log sensitive information unnecessarily.

Acceptance Criteria

  • Passwords hashed, JWT/refresh-token flow secure
  • Every protected endpoint has authorization guard
  • Tenant isolation enforced on all school-scoped queries
  • File uploads validated for type and size
  • Audit log records critical academic actions
  • No client-provided auth data trusted
