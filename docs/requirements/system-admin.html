System Admin

Platform operator console for Nabta staff — manages schools and platform health, not school academic features.

Purpose

SYSTEM_ADMIN users operate the Nabta platform: onboard schools, monitor API health, and run cross-tenant ops. Lives at apps/system-admin. Distinct from school ADMIN who manages a single tenant in apps/web.

v1 Capabilities (Phase 1c bootstrap)

AreaContent
AuthSYSTEM_ADMIN login; JWT flow shared with API
DashboardPlatform overview — school count, health status placeholders
SchoolsList schools; create/edit tenant records (name, slug, status)
HealthSurface API /api/v1/health status (DB, Redis)
ShellApp layout, EN/AR, light/dark theme — same design tokens as web

Stack

  • React 19 + Vite + Tailwind CSS v4 + HeroUI v3 (@heroui/react + @heroui/styles)
  • Shared packages/i18n for EN/AR
  • Dev port 5175; pnpm dev:system-admin
  • Dockerfile.system-admin and Docker Compose profile

In Scope (Phase 1c)

  • apps/system-admin scaffold with auth shell and operator layout
  • SYSTEM_ADMIN role and API guards
  • School tenant list and basic CRUD
  • Platform health dashboard (read-only)
  • EN/AR with RTL support
  • Light/dark theme toggle

Out of Scope

  • School academic features — classes, subjects, assignments, grades
  • Student or teacher portal functionality
  • Billing or payment configuration (future)
  • Impersonating school users

Acceptance Criteria

  • SYSTEM_ADMIN can log in to apps/system-admin
  • Non–SYSTEM_ADMIN users cannot access the console
  • School tenant list renders with create/edit
  • Health page reflects API health check
  • EN/AR and RTL work; light/dark themes work
  • Runs via Docker Compose (--profile full) on port 5175
