Nabta

Internationalization

Bilingual support for Egyptian international schools — English and Arabic from day one.

v1 Languages

LocaleDirectionStatus
English (en)LTRRequired — Phase 1 scaffolding
Arabic (ar)RTLRequired — Phase 1 scaffolding

Architecture must support additional locales in the future (e.g. French, German) without rewriting the i18n system.

Scope — All Six Clients

  • School portals — student, teacher, admin (apps/web)
  • Marketing site (apps/marketing)
  • System admin console (apps/system-admin)
  • Mobile student app (apps/mobile-student)
  • Mobile staff app (apps/mobile-staff)
  • System emails and notifications (when implemented)
  • Date, time, and number formatting per locale

Implementation

  • packages/i18n — shared translation files (en.json, ar.json)
  • react-i18next in web Vite apps (apps/web, apps/marketing, apps/system-admin)
  • react-i18next + Expo in mobile apps (apps/mobile-student, apps/mobile-staff)
  • RTL layout via dir="rtl" on <html> when Arabic is active
  • Logical CSS properties (ms-, me-, ps-, pe-) — avoid hardcoded left/right
  • Locale switcher in app shell, marketing header, system-admin header, and mobile settings
  • Locale persisted in user profile; browser Accept-Language as fallback for unauthenticated users

Rollout Strategy

Phase 1: i18n scaffolding + EN/AR shell strings (navigation, auth, common UI, errors).

Per feature phase: translate new feature strings as they are built — do not defer all translation to the end.

RTL Considerations

  • Sidebar and navigation mirror correctly in RTL
  • Icons with direction (chevrons, arrows) flip appropriately
  • Tables and forms remain readable in RTL
  • Both light and dark themes work correctly in RTL

Acceptance Criteria

  • User can switch between English and Arabic
  • Arabic renders with correct RTL layout
  • Locale preference persists across sessions
  • Dates and numbers format per active locale
  • All Phase 1 shell UI is translated in both languages
