Search & Files

Global search across academic entities and abstracted file storage for all media types.

Global Search

Search across relevant entities:

  • Students, teachers, classes, subjects
  • Lessons, assignments, materials

Use PostgreSQL full-text search initially. Keep the search abstraction extensible so Elasticsearch/OpenSearch can be introduced later if required.

File Management

Design file handling separately from academic entities.

File Types

  • PDFs, videos, images, documents
  • Assignment submissions

Storage Rules

  • Do not store large files directly in PostgreSQL
  • Use object storage abstraction via StorageService interface
  • Local dev: MinIO in Docker Compose (S3-compatible) — not flat local filesystem
  • Production: AWS S3, Cloudflare R2, or GCS via same interface
  • Storage provider swappable via configuration without changing business logic

Structured File Keys

All files stored with predictable, tenant-scoped paths:

{schoolId}/
  materials/{subjectId}/{lessonId}/{uuid}.{ext}
  assignments/{assignmentId}/{uuid}.{ext}
  submissions/{assignmentId}/{studentId}/{uuid}.{ext}
  announcements/{announcementId}/{uuid}.{ext}
  avatars/{userId}.{ext}

Security

  • Pre-signed URLs for upload and download — never public buckets
  • MIME type validation and file size limits on upload
  • Database stores storageKey, mimeType, size, checksum — not file bytes

Acceptance Criteria

  • Global search returns results across students, teachers, classes, subjects, lessons, assignments
  • Files stored in MinIO (dev) via storage abstraction, not in database blobs
  • File keys follow structured naming convention
  • File upload validates type and size; uses pre-signed URLs
  • Storage provider can be swapped via configuration
