Portal Patterns

Composition recipes for school portals — flat bordered chrome, HeroUI for controls. Student is the reference; teacher, school admin, and system admin copy these patterns, not a second visual system.

Reference: apps/web student routes. Phase 7 student polish is shipped. Next: teacher, then school admin, then apps/system-admin. Do not invent a parallel card language.

Principle

Page chrome is a 1px rounded-xl border border-border shell with no elevation or shadow. HeroUI v3 is for controls — Button, Chip, Alert, ProgressBar, Radio, Checkbox, Toast, Skeleton, Modal — not as the default wrapper for lists, queues, or tiles.

Color stays on tokens: --accent / bg-accent/10, --warning, --danger, --success. No rainbow subject palettes.

Panel

Padded facts block. Use for class details, assignment brief, quiz overview, score/feedback.

<div class="overflow-hidden rounded-xl border border-border p-5">
  <dl class="grid grid-cols-2 gap-4">
    <div class="min-w-0">
      <dt class="text-xs font-medium text-muted">Label</dt>
      <dd class="mt-0.5 text-sm">Value</dd>
    </div>
  </dl>
  <!-- optional: border-t border-border pt-4 mt-5 for instructions, files, or a primary action -->
</div>

Student code: StudentPanel in apps/web/src/features/student/StudentChrome.tsx. Later portals may copy the classes or lift a shared helper — do not wrap this in HeroUI Card.

List

Queues and grouped work (assignments, quizzes, to-do, lessons). One bordered ul; rows are links.

<ul class="overflow-hidden rounded-xl border border-border">
  <li class="border-b border-border last:border-b-0">
    <a class="flex w-full items-start gap-3 px-3 py-2.5 text-start text-inherit no-underline hover:bg-overlay …">
      <div class="min-w-0 flex-1">
        <p class="truncate font-medium">Title</p>
        <p class="mt-0.5 truncate text-xs text-muted">Meta · due</p>
      </div>
      <!-- HeroUI Chip: status -->
    </a>
  </li>
</ul>
  • Overdue: text-danger on the subtitle, not a heavy left border on the whole row
  • text-start so RTL stays correct
  • Group with an h2 and count, then one list per group

Student code: StudentList. Do not use WorkItemCard or elevated cards for queues.

Tile

Keep the content stack (icon hero, title, meta, progress) but the outer shell is the same 1px border. Class cards: accent-tinted hero with a selective lucide-animated icon on hover, then name, code/class/teacher, then ProgressBar.

<div class="overflow-hidden rounded-xl border border-border transition-colors hover:border-accent/40">
  <div class="flex h-24 items-center justify-center bg-accent/10 text-accent md:h-28">…icon…</div>
  <div class="space-y-2 p-4">…title, meta, progress…</div>
</div>

Page header and trail

In-page header: h1 (text-2xl font-semibold), optional text-sm text-muted subtitle, optional trailing Chip. Breadcrumbs live in the app shell: Role › section › page. Parent crumbs are React Router links; the last crumb is inert. Mobile may show the last two crumbs.

Student code: StudentPageHeader, usePageTrail in apps/web/src/layouts/PageTrail.tsx.

Status

HeroUI Chip size="sm" variant="soft". Semantic colors: success for submitted/graded/correct, warning for draft/in progress/returned, danger for late/overdue/incorrect, default for not started. Do not invent a second badge system.

Exceptions

  • Continue learning — accent-tinted surface (border-accent/20 bg-accent/10), not a generic card
  • File dropzone — dashed border inside a panel, not a second elevated card
  • Quiz attempt — sticky timer/progress bar above questions; each question is a bordered panel

Quiz review

Details panel first (subject, counts, time, passing, attempts, score). Then one panel per question: prompt, then divided option rows. Mark state with chips: Correct, Your answer, Incorrect. Student code: QuizAnswerReview.tsx.

Empty, loading, error

Follow UX States. Empty: bordered surface, short copy, optional lucide-animated icon. Loading: layout-shaped Skeleton. Error: HeroUI Alert plus retry. Success: Toast or navigation.

Do / don’t

DoDon’t
1px bordered shells for lists, panels, tilesHeroUI Card as the default page chrome
Token colors onlyA unique hue per subject
Static Lucide in content; lucide-animated on selected hover/empty CTAsAnimate every icon
Logical CSS (ms-, ps-, text-start)Left/right physical properties
Check ~375px for overflowAssume desktop grids survive on a phone

Reuse in other portals

Copy the class recipes above into teacher, school admin, and system-admin screens. You may keep Student* names in student code; other portals should not import student feature files. Lift a shared helper under apps/web/src/components/ only when duplication starts to hurt.

System admin (apps/system-admin) uses the same HeroUI + Nabta tokens — apply the same shells there.
