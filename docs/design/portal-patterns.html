Portal Patterns

Composition recipes for school portals — flat bordered chrome, HeroUI for controls. Student is the reference; teacher, school admin, and system admin copy these patterns, not a second visual system.

Reference: apps/web student routes. Phase 7 student polish is shipped. Next: teacher, then school admin, then apps/system-admin. Do not invent a parallel card language.

Principle

Page chrome is a 1px rounded-xl border border-border shell with no elevation or shadow. HeroUI v3 is for controls — Button, Chip, Alert, ProgressBar, Radio, Checkbox, Toast, Skeleton, Modal. Lists, queues, and subject tiles stay a bordered ul or div, not Card. Featured/performance surfaces (quiz list cards, grades hero, Continue learning, quiz overview facts) may use HeroUI Card with bg-surface.

Color stays on tokens: --accent / bg-accent/10, --warning, --danger, --success. No rainbow subject palettes. Accent fill is for controls only (selected option, progress bar, current navigator item) — not whole sections.

Canvas vs view

Page canvas: --background (#f8faf9)
View:        rounded-xl border border-border bg-surface (#ffffff)
Row hover:   hover:bg-overlay
Accent fill: controls only

Views sit on the tinted page. Do not leave panels transparent (they blend into the canvas) and do not wash a whole list in bg-accent/5.

Panel

Padded facts block. Use for class details, assignment brief, quiz overview, score/feedback.

<div class="overflow-hidden rounded-xl border border-border bg-surface p-5">
  <dl class="grid grid-cols-2 gap-4">
    <div class="min-w-0">
      <dt class="text-xs font-medium text-muted">Label</dt>
      <dd class="mt-0.5 text-sm">Value</dd>
    </div>
  </dl>
  <!-- optional: border-t border-border pt-4 mt-5 for instructions, files, or a primary action -->
</div>

Student code: StudentPanel in apps/web/src/features/student/StudentChrome.tsx (PortalPanel includes bg-surface). Later portals import portal helpers. Use Card only when the block is a featured surface, not a facts dump.

List

Queues and grouped work (assignments, to-do, lessons, grades subjects). One bordered ul; rows are links. Global quizzes use Card, not this list.

<ul class="overflow-hidden rounded-xl border border-border bg-surface">
  <li class="border-b border-border last:border-b-0">
    <a class="flex w-full items-start gap-3 px-3 py-2.5 text-start text-inherit no-underline hover:bg-overlay …">
      <div class="min-w-0 flex-1">
        <p class="truncate font-medium">Title</p>
        <p class="mt-0.5 truncate text-xs text-muted">Meta · due</p>
      </div>
      <!-- HeroUI Chip: status -->
    </a>
  </li>
</ul>
  • Overdue: text-danger on the subtitle, not a heavy left border on the whole row
  • text-start so RTL stays correct
  • Group with an h2 and count, then one list per group

Student code: StudentList. Do not use WorkItemCard or elevated cards for queues.

Tile

Keep the content stack (icon hero, title, meta, progress) but the outer shell is the same 1px white view. Subject cards: accent-tinted icon well inside a bg-surface tile, then name, teacher, counts, then ProgressBar.

<div class="overflow-hidden rounded-xl border border-border bg-surface transition-colors hover:border-accent/40">
  <div class="flex h-24 items-center justify-center bg-accent/10 text-accent md:h-28">…icon…</div>
  <div class="space-y-2 p-4">…title, meta, progress…</div>
</div>

Metric

Dashboard stat tile: icon well + label + value. Same white bordered view as lists. PortalMetric uses bg-surface, not bg-overlay.

Page header and trail

In-page header: h1 (text-2xl font-semibold), optional text-sm text-muted subtitle, optional trailing Chip. Breadcrumbs live in the app shell: Role › section › page. Parent crumbs are React Router links; the last crumb is inert. Mobile may show the last two crumbs.

Student code: StudentPageHeader, usePageTrail in apps/web/src/layouts/PageTrail.tsx.

Status

HeroUI Chip size="sm" variant="soft". Semantic colors: success for submitted/graded/correct, warning for draft/in progress/returned, danger for late/overdue/incorrect, default for not started. Do not invent a second badge system.

Exceptions

  • Continue learning — white Card with bg-surface, not bg-accent/10
  • File dropzone — dashed border inside a panel, not a second elevated card
  • Quiz attempt (focus mode) — hide shell sidebar, header trail, and mobile bottom nav on /assessments/:id/attempts/:attemptId (not /result). Top bar is Exit · title · timer. One question at a time; navigator on desktop, Questions modal on mobile

Focus mode

Detected in AppShell when the path ends at an in-progress attempt. Result uses the normal student shell. Exit confirms leave; progress stays saved.

Grades hub

Read-only performance overview: overall-average hero (Card + large % + progress), compact subject list (desktop rows / mobile stacked cards), recent graded work linking to the assignment or quiz. No last-term comparison, qualitative labels, or leaderboards until the API has them.

Quiz review

Lives on the result page only. Overview shows a score plus a link — do not embed the full review there. Each question is a panel: prompt, divided option rows, chips for Correct / Your answer / Incorrect. Student code: QuizAnswerReview.tsx.

Empty, loading, error

Follow UX States. Empty: bordered surface, short copy, optional lucide-animated icon. Loading: layout-shaped Skeleton. Error: HeroUI Alert plus retry. Success: Toast or navigation.

Reuse in other portals

Teacher Home

A prioritized work queue, not a widget dump. Stable order: greeting → quick actions → today’s classes → needs your attention (two columns: to grade + alerts) → recent activity. Quick actions use an inset rounded icon well with card padding — the accent fill does not touch the border. Class tiles keep the full-bleed accent hero band. Today’s classes use a bordered list with status chips and primary actions. Needs your attention shows the top few real rows per column (assignment links, not a quiz-review queue). Activity is a compact timeline from the teacher dashboard payload. Teacher teal #16876F stays on html[data-portal="teacher"].

Teacher class workspace

Hero panel (icon, subject, class, student count) plus URL tabs: Overview · Students · Lessons · Assignments · Quizzes · Attendance · Materials. Queues stay lists; the roster and gradebook stay tables. Course builder remains a full page for drag-and-drop. Do not add Attendance, Lessons, or Materials to the main sidebar.

Shared helpers live in apps/web/src/components/portal/PortalChrome.tsx (PortalPanel, PortalList, PortalPageHeader, PortalEmptyState, IconWell, PortalProgress, PortalMetric) and PortalTabs.tsx (PortalTabs, PortalFilterChips, PortalNavTabs). Student pages keep Student* re-exports. Teacher and later portals import portal helpers — do not import student feature files. Do not invent a second visual system.

System admin (apps/system-admin) uses the same HeroUI + Nabta tokens — apply the same shells there.
