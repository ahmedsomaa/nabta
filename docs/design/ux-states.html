UX States

Every feature must handle all four states — no blank screens.

Loading

Use HeroUI Skeleton (or Spinner for blocking actions) that match the final layout shape. Avoid full-page spinners for partial data loads.

Empty

Explain why there is nothing to show and provide a clear CTA (e.g. "No assignments yet — check back Monday" or "Create your first class"). Optional lucide-animated icon for polish — not required on every empty state.

Error

Human-readable message with a retry action — HeroUI Alert or inline field errors. Never expose stack traces or internal error codes to end users.

Success

Confirm the action completed — HeroUI Toast, inline message, or navigation to the result. Especially important for submissions and grade saves.

Acceptance

  • All screens have loading, empty, error, and success states
  • Keyboard navigable with visible focus states
  • Light and dark theme toggle works with persisted preference
